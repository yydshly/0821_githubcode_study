    06 / RESEARCH ARCHIVE

    这项研究是怎样形成的？

    当前阶段已经归档：保留资源、方法、数据与演示，不进行无目标的第三方 API 全量实测。

    STATUS · 2026-08-22 ARCHIVED

    以后出现农业、环境、物种分布或公共统计等明确产品需求时，再从候选中选择 2–5 个 API 做真实核验、统一适配和二次开发。

    1. 01
      理解资源本质

      确认上游是人工维护的 API 资源索引，不是统一调用网关；目录负责发现，生产能力仍需验证。

    2. 02
      固定并解析快照

      保存 README、提交 SHA 与同步时间，将 1,695 个上游条目结构化为可复现的 JSON、CSV 和统计摘要。

    3. 03
      从分类走向场景

      建立数据对象、常见输入、字段示例与业务问题，把宏观分类转换成 324 个已有候选的具体使用场景。

    4. 04
      补充可追溯扩展

      以独立来源加入 12 个农业官方 API，明确区分 public-apis 上游事实与本项目官方文档复核结果。

    5. 05
      建立诚实边界

      准备度分数只反映 HTTPS、CORS、认证和目录说明；不把存活率、延迟、价格、许可或数据质量包装成已验证结论。

    6. 06
      阶段归档，按需重启

      保留同步、测试、搜索与来源模型；未来围绕具体产品垂直验证，而不是盲目调用全部 1,707 条记录。
