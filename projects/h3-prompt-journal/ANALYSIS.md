# H3 Prompt Journal 能力分析

## 1. 仓库真正提供什么

在研究快照 `0c7b488` 中，上游仓库只有 Markdown、图片和一个结果视频，没有程序入口、依赖清单、API 封装、测试脚本或参数化模板。因此上游提供的是 **可阅读、可复制、可比较的经验资产**，而不是可执行生成器。本研究网页在此基础上新增了一个本地参数化层，但不改变对上游能力边界的判断。

它的能力可以拆成三层：

1. **问题诊断**：从“模型为什么总是切镜、同步、静止、3D 化或表演僵硬”开始。
2. **控制策略**：把抽象意图转换成模型更容易维持的具体规则。
3. **生产提示词**：保存最终提示词和作者对结果的文字描述，部分案例附参考图片或成片。

## 2. 六个案例形成的能力地图

| # | 案例 | 主要失败模式 | 核心策略 | 可迁移能力 |
| --- | --- | --- | --- | --- |
| 001 | 三人遮挡衔接环绕长镜头 | “前往下一个人”被解释为切镜、瞬移或变形 | 用前景遮挡作为物理衔接机制 | 连续运镜、多人身份锁定、统一空间 |
| 002 | 双人 3:1 速度差舞蹈 | “快/慢”被收敛为同步动作 | 用动作数量比例与观察后模仿解释延迟 | 数字化节奏差、非同步编舞 |
| 003 | 单人三姿态微型相机飞行 | 参考姿态被当作停留终点，形成幻灯片 | 把姿态定义为途经锚点，相机承担主动运动 | 姿态过渡、高密度连续运镜 |
| 004 | 多参考帆板时尚 MV | 多张参考图互相争夺控制，高潮被构图图限制 | 给每张图分配职责，高潮段移除摄影参考 | 多参考分工、分段生成、音乐峰值对齐 |
| 005 | 水上闯关综艺 | 逐动作写死导致表演僵硬；完全放开又失去剧情 | 锁定七个剧情锚点，明确授权模型自由执行 | 综艺、喜剧、即兴表演、故事骨架 |
| 006 | 2D 贴纸进入真实厨房 | 2D 角色被 3D 化；盐罐默认出现盖子 | 把平面媒介提升为身份属性，封闭式否定道具先验 | 混合媒介、道具约束、毫秒笑点 |

## 3. 五种可复用控制原语

### 3.1 参考图职责分离

不要只写“参考图 1、2、3”，而要声明每张图控制什么、明确不控制什么。案例 001 将环境主权只给 Picture 1；案例 004 将人物、装备和摄影指导拆成不同职责，并在高潮段主动减少参考输入。

### 3.2 连续物理逻辑

“不要切镜”只是负面条件，不能提供生成路径。案例 001 用肩膀、头发或背部形成前景遮挡；案例 003 把相机定义为一个有惯性、会避让身体的极小飞行点。它们都给出了可以生成下一帧的物理因果。

### 3.3 把形容词变成可检查规则

案例 002 将“一快一慢”变成 3:1 动作数；案例 006 用 `00:03.000`、`00:05.000`、`00:08.000` 固定笑点；案例 004 用音乐功能而不是等长分段驱动动作峰值。

### 3.4 锁定与放权的预算

精密摄影需要强约束，表演型内容需要可控自由。案例 005 最能说明这一点：锁定故事发生顺序，同时明确允许模型决定躲避动作、机位、剪辑节奏与观众反应。

### 3.5 用身份约束对抗风格漂移

案例 006 不把“2D 平面”当成可牺牲的风格，而把它写进角色身份；当某个属性必须跨镜头保存时，这种表达比一般审美形容更强。

## 4. 适用场景

| 场景 | 为什么适用 | 推荐从哪个案例开始 |
| --- | --- | --- |
| 多人物连续长镜头 | 有明确的身份、空间与遮挡控制 | 001 |
| 双人差速或非同步动作 | 可以把速度差转化为数量比例 | 002 |
| 多姿态参考转动态视频 | 需要避免“到达后停住” | 003 |
| 多参考图商业短片 | 需要拆分人物、产品、机位职责 | 004 |
| 综艺、喜剧、自然反应 | 需要在故事可控与表演自然之间平衡 | 005 |
| 2D/3D、真人/动画混合媒介 | 需要保护媒介属性并打破道具先验 | 006 |
| Prompt review 与教学 | 每个案例都有“问题—突破—结论—最终提示词”结构 | 全部 |

不适合直接拿来做：通用一键生成平台、模型性能基准、不同版本的定量对比、批量 API 生产或自动提示词优化。仓库目前没有这些执行层和评估层。

## 5. 证据强度与局限

### 源码直接可确认

- 6 个案例均包含 README 与完整 `prompt.md`。
- 案例 004 附 4 张参考图片和 1 个结果视频；案例 006 附 1 张参考图片。案例 004 README 描述 45 秒成片，但所附视频的浏览器媒体时长约为 36 秒，两者存在差异。
- 仓库使用 MIT License。
- 部分案例采用官方六段式字段，另一些采用自由结构的长提示词。

### 作者报告、但缺少对照实验

- 3:1 比例能够稳定保持速度差。
- 命名后的镜头语法能减少切镜或瞬移。
- 将平面媒介写成身份属性能抑制 3D 化。
- 明确放权能让喜剧表演更自然。

这些都是值得复用的经验假设，但仓库没有记录种子、模型构建号、生成参数、失败输出、重复成功率或 A/B 对照，因此不能把它们当成已量化的普遍规律。

### 兼容性提醒

研究时读取的官方 `h3-prompt-writing` 技能写明基础时长应为 **4–15 秒**；案例 001 和 005 使用 20 秒规格，案例 004 通过 3 个 15 秒片段组合为 45 秒。这说明案例实践与当前官方写作指南之间存在需要重新验证的边界，而不是可以无条件照搬的参数保证。

## 6. 可扩展方向

### P0 — 把日志变成可复现实验

- 为每次生成记录模型版本、输入模式、分辨率、时长、种子、日期和成本。
- 保存失败样本、成功样本和同参数复跑结果。
- 给每个结论增加“观察次数 / 成功次数 / 判断指标”。

### P1 — 把案例变成参数化提示词系统

- 抽取统一 schema：参考职责、锁定项、自由项、时间线、物理逻辑、负面约束、音频。
- 将六种策略做成可组合模块，而不是复制整篇长提示词。
- 增加模式与时长校验，阻止不兼容的 H3 配置。

本研究演示页已完成 P1 的第一版：六种策略均有公共字段、参考职责、专属参数和约束开关，并按当前官方顺序输出六段式 Ref2VA Prompt；它尚未提供模板持久化、组合多个策略或真实生成回归。

### P2 — 建立自动评估与回归

- 对身份一致性、镜头切换、动作比例、时间锚点和媒介漂移建立可观察指标。
- 自动抽帧、检测镜头边界，输出时间线证据。
- 对每次 H3 版本升级运行固定测试集，生成回归报告。

### P3 — 产品化

- 形成“需求 → 选择策略 → 上传参考 → 生成结构化 Prompt → 运行 → 评估 → 迭代”的工作台。
- 接入 `video-to-h3-prompt`，让反推结果可直接进入案例库。
- 增加版本、模板、团队批注与结果谱系，但把真实 API、密钥和计费留在独立后端。
