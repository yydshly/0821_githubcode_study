# H3 Prompt Journal 阶段性结项档案

> 归档日期：2026-08-21 · 状态：`archived` · 研究范围：上游 6 个案例 + 本研究 6 次外部 MiniMax H3 实测

## 结论先行

本轮研究已经完成一次**全案例覆盖性验证**：六种策略各完成一套可执行前置信息、输入素材、外部生成、画面与声音检查、失败归因。它足以回答“这个仓库是什么、有什么价值、是否能直接当生产模板使用”，但不是多次重复生成后的统计基准，不能据此计算稳定成功率。

最终判断是：

1. 上游仓库最有价值的不是六份可复制 Prompt，而是六个“失败模式 → 控制策略”的推理案例。
2. 长模板适合作为**诊断清单和策略词典**，不适合作为不经改写的生产默认值。
3. 本研究直接从参数化模板生成的五个复杂样例，都出现了不同程度的目标错配、任务过载、可观察性不足或物理关系失败；它们并未证明“字段越完整，质量越高”。
4. CASE 006 的 2D 柠檬贴纸厨房喜剧是本轮总体效果最好的一例，但仍出现盐罐盖子偏差，不能称为完全通过。
5. 后期若继续使用，应由 AI 围绕具体素材和唯一核心目标进行删减、消冲突和重写，再由人确认目标，最后外部生成并复盘。AI 能提高提示词质量，但不能保证单次成功。

因此，本项目在当前问题已经回答后阶段性归档；不再为了“把模板证明为有效”而继续堆样例。

## 六次真实测试总表

| 案例 | 实际结果 | 核心判断 | 是否建议直接复用 V1 |
| --- | --- | --- | --- |
| 001 三人物遮挡长镜头 | 三身份与环境基本保持；独立环绕和遮挡交接不完整 | 任务密度过高，空间路径与遮挡量化不足 | 否 |
| 002 双人 3:1 差速 | 下载文件画幅正常，但全片裁掉双脚且存在切镜 | 目标动作不可观察；模板内部“全身动作 / 近距腰上镜头”直接冲突 | 否，V2 仍待验证 |
| 003 三姿态微型飞行 | 身份和姿态顺序保持；成片像人体扫描，微型飞行语法失败 | 结构控制通过，但模板检查项压制了审美与表演 | 否 |
| 004 多参考帆板时尚 | 人物、装备、摄影职责粗粒度进入成片；装备连接和水上物理失败 | 参考职责能控制“有什么”，不能替代逐帧运动学 | 否 |
| 005 水上闯关综艺 | 多数剧情节点和对白出现；机关因果链断裂 | 15 秒内节点、对白和放权过多；节点出现不等于故事成立 | 否，V2 仍待验证 |
| 006 2D 贴纸厨房喜剧 | 媒介身份、主要动作和喜剧节拍最完整；盐罐盖子仍漂移 | 单主体、单参考职责、短因果链更匹配模型能力 | 可作起点，仍需按素材复核 |

这六次测试共同揭示：**提示词控制的首要问题不是格式是否完整，而是核心目标是否唯一、能否被镜头观察、动作是否能在时长内完成、各约束是否互相兼容。**

## 上游仓库的真实价值

### 1. 提供了一套失败模式词典

上游没有可执行程序、API 封装或自动优化器，但它系统记录了切镜、同步、姿态停滞、多参考冲突、表演僵硬、媒介 3D 化等常见问题。以后遇到相似症状时，可以快速定位可能需要的控制原语，而不是从空白提示词重新摸索。

### 2. 展示了如何把抽象意图改成可执行规则

仓库中最值得迁移的方法包括：

- 为每张参考图分配唯一职责，并写明“不控制什么”。
- 用空间路径、遮挡和接触关系描述连续性，而不只写“不要切镜”。
- 把“更快、更慢、更好笑”改成动作数量、时间点和事件顺序。
- 区分必须锁定的因果骨架与可以交给模型的细小表演。
- 把 2D、剪纸、贴纸等媒介属性提升为角色身份，而不是普通风格形容词。

这些是可组合的控制原语，不等于六套完整 Prompt 必须整体继承。

### 3. 是优质的提示词复盘教材

其“问题—尝试—突破—最终提示词”结构比只展示成功成片更有教学价值。真正可复用的是设计推理：为什么添加某条约束、它试图压制哪种模型先验，以及为此牺牲了多少自由度。

### 4. 暴露了当前经验型 Prompt 仓库的证据缺口

上游缺少统一的模型版本、生成参数、种子、失败样本、重复次数和 A/B 对照。本研究的实测进一步说明，作者经验和长提示词结构不能自动转化为稳定生产能力。这一缺口本身也是重要结论：以后评估类似仓库，必须把“有完整 Prompt”与“经过可复现实验验证”分开。

## 对我们后期的意义

### 意义一：形成一套更成熟的开源项目研究方法

以后研究生成式 AI 仓库，不再停留在 README 解读或功能演示，而要完成以下证据链：

```text
上游声称的能力
→ 可执行前置信息
→ 真实外部输出
→ 输入 / 输出并列保存
→ 画面、声音和元数据检查
→ 通过项、失败项与归因边界
→ 是否值得继续投入
```

本项目已经沉淀了输入证据持续可见、原始失败结果不被覆盖、修复稿标注“待验证”、下载文件与平台预览分开判断等研究规范。它们可以直接复用于后续子项目。

### 意义二：建立提示词质量审查的四个优先级

后续任何视频提示词，应先检查：

1. **目标唯一性**：这次最重要的是身份、动作、镜头、因果还是审美？只能有一个第一目标。
2. **可观察性**：镜头是否真的展示要验证的动作、接触点、比例或尺度？
3. **可执行密度**：时长是否容纳人物数、事件数、对白、运镜和声音要求？
4. **语义一致性**：全身 / 近景、连续长镜头 / 切换机位、精确因果 / 广泛放权等要求是否互相打架？

只有这四项通过后，六段式结构、声音细节和负面约束才有意义。

### 意义三：明确“AI 辅助改写”比“模板直接复制”更合理

后期可把仓库作为 AI 的参考知识，而不是让人手工填满全部字段。AI 应执行的是：理解素材、选择少量相关策略、删除无关规则、发现冲突、估算任务密度、把关键结果改写为可观察事件。人负责确认真正想要的效果和可以接受的取舍。

### 意义四：为是否产品化提供了清晰门槛

现在不应继续扩建一键模板生成器。只有当我们能取得同设置多次生成结果，并证明某个轻量定制方案在成功率、可控性或迭代成本上优于自由提示词，才值得进入自动评估、版本回归或 API 产品化阶段。

## 后期推荐使用方式

### 推荐流程

1. 用一句话定义唯一核心结果，例如“全片必须看见四只鞋并验证 3:1 步数”，不要先选完整模板。
2. 从六案例中只抽取与失败模式相关的 1–3 个控制原语。
3. 让 AI 根据具体输入图、时长、画幅和声音目标生成**轻量定制稿**。
4. 在生成前完成四项检查：目标唯一、结果可观察、时长可执行、约束无冲突。
5. 人工删除不影响核心结果的镜头、剧情、形容词和负面约束。
6. 把英文生产稿与参考图按编号交给外部 MiniMax H3；中文稿只用于理解和复核。
7. 保留原始输入、Prompt、参数和 MP4，按“通过 / 偏差 / 无法判断”复盘。
8. 只有真实结果证明修复有效，才能把修复稿升级为可复用方案。

### 适合继续查阅本档案的场景

- 多参考图职责冲突，需要明确人物、装备、环境和摄影的主权。
- 生成结果频繁切镜、瞬移、同步或停在参考姿态。
- 需要精确时间点、动作数量比例或可见因果链。
- 2D / 3D 混合媒介或强道具先验需要保护。
- 需要复盘“为什么结构上执行了，观感却更差”。

### 不建议的使用方式

- 不修改素材职责和时间线，直接复制完整模板。
- 认为字段越多、负面约束越长，成片就越稳定。
- 用一条 Prompt 同时验证人物身份、复杂装备、多段剧情、运镜、对白和声音。
- 只看平台预览或最后一帧，不检查下载文件和完整时间线。
- 用修复稿的设计意图替代尚未生成的验证结果。

## 为什么现在归档

研究最初的问题已经得到回答：上游是经验案例库，不是自动提示词生成器；六种方法具有启发和诊断价值，但不应整体模板化后直接生产；本研究的一次全覆盖实测已经揭示模板化的主要边界。继续生成更多不同题材的单次样例，只会重复模型方差，不能提高结论强度。

如果未来重新开启，必须带来新的证据能力，而不是新增题材。满足以下任一条件才值得复研：

- MiniMax H3 模型或参考视频模式发生显著版本变化。
- 可以在相同输入和参数下进行至少多次重复生成。
- 可以执行“自由提示词 / 轻量定制 / 完整模板”的严格 A/B 对照。
- 已有自动抽帧、镜头边界、身份和动作计数等可重复评估工具。
- 有明确生产任务需要验证某一条控制原语，而非泛化地证明整套模板。
