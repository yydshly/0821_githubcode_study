## 这项能力是什么

它不是地理地图，而是项目架构逻辑图。模块被画成建筑，研究领域被画成街区，依赖和成果传递被画成道路，研究过程则变成沿道路移动的载荷。

本研究演示使用上游原始 React/SVG 组件，直接映射我们已经完成的 GitHub 能力研究实验室，展示：

- H3 Prompt Journal、ZhuLink、Moovie 和 Architecture Map 4 个真实研究项目；
- 研究规则、选题模板、实验室、证据归档、研究展厅和 Pages 发布流水线；
- 14 个模块、5 个街区、16 条关系；
- 新增研究、H3 结项、Moovie 来源实验、ZhuLink 归档 4 条可播放流程；
- 点击建筑查看职责、设计决策和代表性文件；
- 直接扫描当前仓库 90 个真实代码/文档文件及约 1.74 万行文本；
- 自动生成建筑尺寸、布局与 `UNCLAIMED` 漂移计数；
- 五个街区使用稳定的语义配色，建筑、地块、旗帜和左侧索引保持一致；
- 本地研究修复使用建筑起始位置进行远近排序，避免宽建筑错误覆盖前排建筑；
- 拖动画布、滚轮缩放、暂停和调整流程速度。

公开在线版位于 `docs/demos/architecture-map/`。由于固定上游版本没有许可证，公开版没有复制或编译上游文件，而是依据本研究确认的架构数据，独立实现静态 SVG 渲染、正确遮挡、模块选择和流程播放。

## 两个核心扩展方向

1. **地图表现能力**：继续扩展颜色、建筑类型、层级细节、版本差异、风险叠层和大型仓库渲染，让视觉形式稳定表达架构语义。
2. **项目理解入口与流程驱动**：从用户问题进入项目，通过源码证据、真实流程、影响分析和增量更新，带着用户阅读和验证代码。

完整范围、当前能力与推荐顺序见 [EXTENSIONS.md](EXTENSIONS.md)。

## 研究问题

- 上游能否在不引入图形库的情况下生成可用的交互式架构地图？
- “人工/Agent 编写语义，脚本测量数量与几何”的混合方法是否可复现？
- 新增源码文件后，漂移检查能否发现地图落后？
- 宣传的 CI 防漂移能力与实际脚本行为是否一致？

## 快速开始

要求 Node.js 22 或更高版本，因为上游脚本使用 `node:fs` 的 `globSync`。

```powershell
cd projects/architecture-map
npm install
npm run dev
```

打开 <http://127.0.0.1:4178/>，建议按以下顺序体验：

1. 点击左侧“Moovie 来源实验”，观察上游源码如何进入实验室、结论页、展厅和 Pages；
2. 使用页头的暂停和 `0.5× / 1× / 2×` 调速；
3. 点击“H3 Prompt Journal”，查看 24 个真实研究文件、约 1564 行内容和代表性文档；
4. 拖动画布、滚轮缩放，按 `0` 回到全景；
5. 查看页头 `Unmapped`，当前应为 `none`。

构建与检查：

```powershell
npm run build
npm run check:map
```

## 漂移实验

新增一个尚未进入地图的新研究项目，例如 `projects/new-research/README.md`，然后运行：

```powershell
npm run check:map
```

生成文件尚未同步时检查会失败。再运行 `npm run sync` 后，页面的 `Unmapped` 会显示新增文件数量。值得注意的是，上游当前不会因为 `UNCLAIMED` 非空而直接返回失败；这也是本研究要记录的能力边界。

## 当前结论

上游的核心展示能力已经在真实浏览器中复现：它确实能把作者定义的架构语义和脚本测得的代码规模组合成可交互逻辑地图。研究同时发现并修复了一个真实绘制缺陷：原排序把建筑宽度与深度计入远近判断，导致宽大的后排建筑可能盖住前排建筑；本地实验改为按足迹起点 `gx + gy` 进行远到近排序。最重要的能力边界也已确认：它能检测生成文件是否过期，但当前不会强制 `UNCLAIMED` 为零，因此不能把现有 `--check` 等同于严格的“架构覆盖门禁”。

本地证据保存在 `evidence/`：首次空白页、JSX runtime 修复后首屏、语义配色、遮挡修复、流程播放和模块选择截图。因为上游许可证未明确，上游复现材料与编译产物不纳入公开仓库。公开 GitHub Pages 演示是独立实现，只复用本研究自己编写的架构事实和说明文本。
